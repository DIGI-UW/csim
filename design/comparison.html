What changes between the options?

Use official Superset for the main CSiM dashboard. The native Custom date editor, prepared queries and reporting-period summary provide specific dates without changing Superset’s application code.

The custom alternative adds month-name-first labels, a sidebar reset repair, inline hospital prompts and validation before Apply. These are experience differences to compare. They are not prerequisites for correct date filtering.

Try the official dashboard first

  1. Open official Superset and select a hospital and location. To compare the custom alternative, use the same selections. The lower hospital comparison uses its own Your hospital selector.
  2. Select November 2025 through April 2026. On the official build enter November 1 as the inclusive start and May 1 as the exclusive end. The custom alternative uses inclusive From and Through months.
  3. Switch Month → Quarter → Year. Read the eleven date axes and hover details, especially the lower comparisons.
  4. On the official build enter February 1 through April 1 and group by Quarter. January must remain excluded.
  5. Use a contents link and confirm the dashboard keeps its current selections. Clear all/reselect remains a known left-sidebar defect on official 6.1.0; reload after Clear all.

A rendering pass does not settle the disputed hospital total or hospital-specific transition dates. Those source questions, processed-data downloads and WordPress access checks remain separate acceptance items.

Clients can edit and version without GitHub

Use Superset for editing and a shared Drive folder for dated release exports. Keep a note of the author, changes, software version and reviewer beside each ZIP and its screenshots.

  1. Export the accepted dashboard before editing in the test installation.
  2. Edit and save the relevant charts/datasets as well as the dashboard. Shared objects affect other dashboards too.
  3. Repeat the checks above and save a new dated release folder.
  4. For transfer or rollback, restore dependencies too. The tested 6.1.0 dashboard-only importer leaves existing chart and dataset definitions unchanged; use the documented asset-import/repair procedure or the tested interface sequence.

Reporting records are managed separately. A Superset dataset export contains the saved query and field definitions, not the PostgreSQL data. Dashboard updates and rollbacks must leave those records untouched.

Dashboard editing does not require a repository checkout. Custom software maintenance still belongs to the administrator. Later automated deployments must reconcile client edits instead of overwriting them.

Development version history and handover acceptance

The pinned development source contains Superset’s own chart/dashboard version-history interface. This is not in the inspected 6.1.0 source. Restoring one dashboard is not a complete rollback of its dependent charts and datasets, and client-role restore still needs a rehearsal.

The handover is accepted after a client editor can edit, export and restore a release without Git, and an administrator demonstrates transfer and backup recovery.
