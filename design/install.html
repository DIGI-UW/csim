Install the dashboard update without replacing the data

This package updates the client's familiar CSiM dashboard on official Superset 6.1.0. It keeps the existing dashboard, reporting datasets, PostgreSQL connection and uploaded source tables. It contains definitions, not patient or reporting records.

What this update changes

UpdatesThe existing Individual Data dashboard, its 21 charts, six saved reporting queries, layout, colors, filters and Table of Contents links.
PreservesThe client's dashboard identity, six reporting-dataset identities, PostgreSQL connection, source-table names and uploaded Current, Historical and hospital-lookup records.
Does not includeDemo records, example dashboards, retired experiments, archived client datasets, a Superset application patch or database credentials.
Separate supporting viewThe Data & records dashboard and individual-record review table remain a separate package. Installing the main update cannot silently add them to the familiar dashboard.

Dashboard definitions and reporting records are separate. This ZIP describes what Superset should display and how it calculates results. It does not carry the rows stored in PostgreSQL.

Before installing

  1. Confirm the destination is the intended official Superset 6.1.0 instance.
  2. Export a fresh backup of the destination dashboard, its charts and datasets. Keep the application metadata backup as the rollback point.
  3. Compare that export with the September baseline. If anyone saved later SQL, chart, layout or filter edits, reconcile them before continuing.
  4. Confirm the destination still uses the existing PostgreSQL connection and the same six reporting datasets.
  5. Rehearse in a copy of the client configuration before updating the live dashboard.

Do not import the public demo dashboard into client production. Its local object identities and demo connection differ from the client's. Use the client update linked on this page.

Installation sequence

  1. Keep the fresh backup

    Record the current destination revision and retain its exported definitions and metadata backup.

  2. Import the client update

    Use the versioned repository importer with the client-update profile. It invokes Superset's normal asset importer, then corrects internal chart references and saved filter scopes that can otherwise retain numbers from the source instance.

  3. Run the definition check

    The verifier compares SQL, calculated columns, measures, chart settings, colors, layout, filter defaults and scopes, and all nine Table of Contents links with the tested release.

  4. Open and review the dashboard

    Check a known hospital and explicit date range before the updated dashboard becomes the accepted client release.

Administrator commands and why the helper is required

From the checked-out release revision, run the importer and verifier inside the configured Superset environment:

python scripts/dashboard_import.py import --profile client-update
python scripts/verify_import.py --profile client-update

Superset assigns local numeric chart identifiers on each instance. Official 6.1.0 can retain source-instance numbers in dashboard layout and cached filter scope. The helper remaps those references to the destination's objects; it does not patch or replace Superset.

What must be true after installation

One familiar dashboard

The update changes the existing dashboard. It does not create a second CSiM Individual Data dashboard.

Six familiar reporting datasets

No duplicate reporting datasets appear, and their saved SQL and measures match the release.

Connection unchanged

The PostgreSQL connection and source tables remain the client's existing ones.

Data still present

A known hospital, reporting month and total still match the pre-installation data check.

Dates and grouping work

Presentation is intact

Rollback

If the destination differs unexpectedly, stop before further edits. Restore the backed-up dashboard, chart and dataset definitions and the matching application metadata backup. Reporting records stay in PostgreSQL and should not be restored or replaced as part of a definition rollback.

After rollback, repeat the known hospital, date, total and filter checks. A dashboard that opens successfully is not enough to prove every relationship was restored.

Known limits and decisions

  • Clear all: official Superset 6.1.0 can retain a stale selection after Clear all and reselect. Reload after using Clear all. This package documents the limitation; it does not add a Superset patch.
  • Importer repair: the versioned reference helper is part of the tested installation path. A manual ZIP upload alone has not passed the same destination-reference checks.
  • Time Unit choices: Month, Quarter and Year remain an installation-wide restriction on this dedicated 6.1.0 instance.
  • Supporting records view: the separate Data & records package still needs destination installation and role checks if the client accepts that workflow.
