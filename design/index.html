The underlying reporting need

For my hospital or a comparison cohort, show results for a chosen care location and date range. Let me switch between monthly, quarterly and annual views while keeping the population, reporting window and calculation rules clear.
  1. Predictable filters across chartsA selection affects the intended charts. Separate comparison groups and intentional exceptions remain clear.
  2. Separate the reporting window from groupingQuarter groups selected observations; it must not expand February–March into January–March.
  3. Readable dates in chronological orderUse Jan 2025 for months, Q1 2025 for quarters and 2025 for years.
  4. Keep missing data distinct from zeroA missing month remains visible. A valid zero and a rate without a denominator mean different things.
  5. Preserve definitions when moving or updatingThe tested SQL, chart settings, dataset bindings and filter scopes must reach the destination together.

In Power BI terms, these involve slicers and visual interactions, a date table, measures and deployment. Here they need to work together within CSiM’s saved Superset dashboard.

Date labels do not follow the selected grouping

Ian described default labels that mix years, months and weekdays. Beth’s fixed Month–Year format improves monthly reporting but still labels quarters and years as months. Turning dates into text can introduce alphabetical sorting.

The text-date workaround drops missing periods

Beth’s alternate time_aggregate approach could sort periods, but a label built from existing rows cannot create a missing month. Her proposed date-table join supplies the absent periods.

Changing and clearing date filters can be confusing

Beth reported a Time Period selection disappearing or becoming stuck while trying combinations of range and grouping. The required behavior is to preserve both choices, obtain equivalent results in either selection order, and recover after clearing on the same page.

Exports contain references that change between instances

Dashboard exports are supported definition files. They include dataset SQL, chart settings, layout and filters; database records are separate. Embedded numeric references must be translated when objects receive new IDs on import.

2. Solutions demonstrated in the dashboard

A reporting window with two month fields

The second snapshot dashboard separates the included months from the grouping. February through March is inclusive: Quarter displays Q1 2026 using those two months only. Changing the grouping preserves both fields. The partial-period note explains the coverage, and Clear all can be followed by new selections on the same page, including the same hospital.

The source records use reporting month and year, so these controls select whole months. They do not imply daily precision. The existing Time Period controls remain available for comparison.

What the solutions require

Chart rendering

Format the label, keep the date

All eleven date axes keep real dates for ordering and display Jan 2025, Q1 2025 or 2025 according to the dashboard’s Time Unit. Hover details use the same format.

The formatter follows the selected unit. Labels sit on real reporting periods, with the first and last period visible and space at each edge. The six stacked-bar legends sit above the plots to leave room for dates. Narrow charts show fewer intermediate labels; observations and hover details are unchanged.

Dataset structure

Supply the missing periods

A calendar join retains months without observations. Missing values remain gaps; a valid 0% remains a plotted value. A missing denominator remains unavailable.

Date filtering

Group only the selected observations

The reporting window applies before calculating each quarter or year. February–March grouped as Q1 excludes January.

The original measure formulas and submission-weighted cohort calculations are retained. Period aggregation uses the selected records instead of choosing the largest monthly rate.

Configuration and version

The snapshot’s native filter definition stores time_grains. Its source is pinned to e22ce197, with a pinned image digest and the versioned CSiM formatter patch. It is a development build, not a preview release.

Keep the dashboard and its tests in Git

The CSiM repository contains the source archives, comparison, demo data, native definition files, image patches and automated tests. Initialization restores the database explicitly; normal dashboard updates do not reseed it.

The transfer checks use a destination with different chart IDs, then change and restore existing SQL, a calculated-column expression, a measure, a chart setting and layout text. The released build’s helper repairs cached references; the snapshot handles those references natively.

See transfer verification →
Why a standard import alone was insufficient

Superset’s dashboard import can preserve shared dataset and chart definitions even when dashboard overwrite is enabled. The complete-assets importer updates those definitions together. Superset 6.1.0 also leaves stale cached filter references; the helper maps them using persistent UUIDs. These are separate import behaviors.

3. Remaining issues and proposed solutions

Released-version limitation

Independent time menus are still a snapshot feature

Superset 6.1.0 does not provide the per-control choice list demonstrated in the snapshot. A dedicated CSiM installation can keep the global restriction. A shared installation needs a tested build containing the upstream feature, or a future release that includes it.

Historical behavior · Cause not established

Unexpected authoring changes need a reproducible case

The test export retains time_aggregate and its original SQL. The saved files do not establish why a different dataset appeared during editing, or why customizations seemed to disappear. The versioned build verifies bindings and calculated columns, but does not claim to fix an unidentified authoring defect.

For a recurrence, keep the affected chart, instance, dataset identity and before/after export. The same applies to the historical intermittent permalink and back-navigation reports.

Other team reports and scope

The team already tracked comparison-menu restrictions, defaults, titles, formatting, navigation and historical data questions. These are accounted for in the issue coverage table; they are not all new fixes.

The inherited table-of-contents links still point to the original test server and its saved filters. Scroll through the demonstration dashboard; replacing those links with local section anchors is a separate navigation correction.

WordPress access and embedding, production changes, data completeness, printing, accessibility and automated data refresh are separate work. The test-only latest-data card is excluded from this baseline.

Why the earlier work was difficult

A fixed date format changes text but cannot supply missing months or choose the correct reporting grain. A text-date workaround can lose chronological ordering. Date filtering and rate aggregation must also happen in the right order. Time Unit menus and import references add version-specific constraints.

The team had issue responses, saved SQL, export backups, a tutorial and a handover. This project adds a reproducible link between those definition files, a pinned build, known test records and observable dashboard checks.

How the source exports differ

April: the selected 20-chart, six-dataset baseline. September test: the same six SQL definitions, a time_aggregate calculated column, fixed month labels and a latest-data card. September production: the same 20-chart inventory, with the historical source table changed in all six SQL definitions and later presentation settings.
