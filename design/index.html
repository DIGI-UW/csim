Standard chart settings · Year-first labels

1. Labels should identify the whole reporting period

Select Quarter. A point still reads “Jan 2025,” so a whole quarter looks like one month.

The correction: preserve date filtering and use labels that identify the selected month, quarter or year. Official Superset uses year-first labels so multiple series stay in chronological order. The custom alternative provides the original requested wording.

Month2025-01
Quarter2025 Q1
Year2025

Demonstrated: the official and custom dashboards retain every monthly label in the eleven date charts at the reviewed widths. Labels rotate to fit. Official wording is 2025-01 · 2025 Q1 · 2025; custom wording is Jan 2025 · Q1 2025 · 2025.

Why this is difficult, and how to maintain it

A fixed Month–Year format stays fixed when grouping changes. Converting dates into text can make them sort alphabetically. The normal automatic date axis does not provide all three agreed formats on one switchable chart.

Through the interface: try the standard date format, label rotation and spacing settings. Separate Month, Quarter and Year views can each use a fixed format, but add charts to maintain. Those alternatives have not yet been shown to satisfy the complete CSiM workflow.

Extra code: our customization supplies the requested wording, but standard alternatives have not been ruled out. The custom formatter retains every requested bucket and uses measured axis space. The official comparison also retains every month, using year-first text labels. Compare the actual results before choosing a build.

Superset direction: 6.1.0 includes rotated-label fixes and automatic-date improvements. Development adds grouping-aware hover labels, such as 2025 Q1, and spacing improvements. Hover labels and axis labels need separate checks.

Supported dataset change · No Superset code change needed

2. The date range and grouping do different jobs

February–March grouped by Quarter should use those two months. January must not be added.

Time PeriodWhich observations to include: February–March.
Time UnitHow to group them: Month, Quarter or Year.

The correction: apply the date window before calculating quarters or years. A partial quarter therefore contains only the selected months.

Recommended controls: open Time Period in the left filter panel. It opens in Custom with Specific Date/Time for both endpoints. The start is included and the end is excluded: February through March means February 1 to April 1. Time Unit groups the selected records into Month, Quarter or Year. The saved opening window is September 1, 2025 to September 1, 2026.

How the dates work, and how to maintain them

CSiM records report a month and year, represented by the first day of that month. These are monthly observations, even though Superset offers a date-and-time picker. Use month boundaries to include complete reporting months.

Through the interface: edit the Time Period filter’s default to a Custom range with two specific dates, then save the dashboard. An explicit range stays fixed. Saving a relative range such as Last year changes how the editor opens.

The eleven date charts follow the window. Overall summaries, latest-submission tables and submission-total cards have separate coverage; they do not all follow Time Period.

A dataset editor maintains the query using supported Superset features. A dashboard editor can reuse it without editing the query.

Known gap in official Superset 6.1.0

3. Clearing a filter must not leave the wrong results

Clear all, then choose the same hospital again. Its name can appear selected while results from other hospitals return.

The official dashboard now uses the familiar left filter panel. Changing individual dates and selections is separate from the known Clear all reset defect. Moving the controls left does not repair that defect.

Cause and available solutions

The vertical filter panel omits a reset notification used by the controls. The horizontal panel passed the same-page recovery checks; the custom build repairs the vertical panel. Ordinary dashboard settings cannot repair this application defect.

To check recovery, compare results before and after Clear all and reselect the same hospital and dates. A correct-looking selection alone is insufficient. Reloading is not evidence of successful recovery.

4. Missing months should not disappear or become zero

January and March have submissions. Without a February row, the chart can hide the gap or suggest an uninterrupted series.

The correction: a calendar supplies every reporting period, including months without observations. Missing observations stay gaps. A valid zero stays a plotted value; a rate without enough information to calculate it stays unavailable.

Why this is difficult, and how to maintain it

A date label cannot create a missing month. This is the date-table approach Beth described from Power BI, implemented in the saved dataset query.

Through the interface: use the prepared dataset. Preserve its calendar logic when editing or replacing it, and avoid filling all missing values with zero. Check one missing month and one known zero after any dataset change.

Standard filters and dataset rules

5. Empty panels need an explanation

Choose Cohort and a hospital-only panel is blank. Does it need a hospital selection, have no data, or contain an error?

Using the dashboard: choose the main hospital or cohort and care location first. Use the separate Your hospital and Cohort/State selectors for the lower comparisons.

Opening behavior: Cohort is selected for the main charts. Instructions ask you to choose a hospital for hospital-only comparisons. Their queries leave an unset hospital blank instead of combining hospitals. Native empty panels remain less explicit than the custom version’s inline prompts.

How to maintain it through the interface

Set defaults and choose which charts each filter affects. Put selection instructions beside the affected panels. Keep “choose a hospital,” “no data for this selection,” and a chart error visibly distinct.

The hospital-only query also needs a rule for an empty selection. This is a dataset/filter configuration concern, not a reason to customize Superset itself.

6. Time Unit should offer useful choices

Monthly reporting offers seconds and minutes. Removing them also removes them from a different dashboard that needs hourly data.

Official CSiM: Month, Quarter and Year are restricted across this dedicated installation. Dashboards on other installations keep their own choices.

Development: each control can save its own list. Preview demonstrates Month/Quarter/Year for CSiM alongside Hour/Day/Week for an hourly dashboard. This feature comes from Superset and needs no CSiM code.

How to maintain it, and what Superset provides

On 6.1.0, an administrator manages the shared list; an editor cannot save an independent list for each dashboard. On development, the editor can save choices per control. Bringing that feature back to 6.1.0 would itself create a custom version.

The available feature comes from native-filter choices and display-control support. Changing the menu alone does not repair date labels or filtering.

Standard section links · Applied to the September dashboard

7. Contents links should stay on this dashboard

A production contents link opens test, or restores an older hospital and date selection.

The correction: link to a section of the current page, without a server address or saved filter selection. The September dashboard uses these local section links.

Why this happens, and how to maintain it

Copying a full dashboard URL can copy its server and saved selections too. In the contents text, use a section link beginning with # and the section identifier. Check the link again if the section is recreated.

After importing, click every contents entry with a hospital and date range selected. The dashboard and selections should stay the same. The earlier 20-chart comparison retains inherited links; use scrolling there.

8. Moving a dashboard must preserve its definitions

Client editing and versioning without GitHub →

Charts appear after import, but a filter controls the wrong charts or a shared dataset keeps an older definition.

The correction: transfer datasets, charts, layout and filter relationships together. On 6.1.0, CSiM also uses a separate deployment helper to repair references the importer leaves behind. Development contains Superset’s own repairs.

What an export contains: dashboard definitions and saved queries. Database records are separate. Importing the ZIP alone does not install our custom Superset features.

Why this happens, and how to maintain it through the interface

Some internal chart numbers change between servers. Shared charts and datasets also need to be updated consistently; renaming a dashboard does not create independent copies of everything it uses.

  1. Edit in a test installation. Keep a dated export before changing anything.
  2. Export the complete dashboard and keep a short note of the changes.
  3. Import into the destination and check dataset definitions, chart settings and filter relationships.
  4. Repeat the date, clearing and navigation checks. A successful upload does not establish that all relationships are correct.

If references remain wrong, an administrator may need the helper. It works alongside standard Superset; it does not fix the importer inside Superset. The public repairs are native-filter references and additional filter references.

The team already had issue tracking and exports. Versioned files add a repeatable way to compare intended definitions with the installed dashboard. They do not explain an editing problem unless its before-and-after state is available.

How the source exports differ

April: the selected 20-chart, six-dataset baseline. September test: the same six dataset queries, an experimental text-date column, fixed month labels and the latest-data card. September production: twenty charts, a changed historical source table and later presentation settings.

The recommended dashboard preserves Beth’s 21 September reporting charts and adds a reporting-period summary using a normal Superset table chart. The April file’s exact historical production identity remains unconfirmed.

Chart settings and data-loading information

9. “Latest data” and percentages need clear wording

A file uploaded in September contains observations through March. “Latest reporting month” means March; it does not mean the upload date.

Current behavior: the latest-data card describes reporting coverage, independently of the viewing window. An automatic “Last successful upload” timestamp is not available.

Percentage charts and comparison tables show whole percentages. The underlying values retain their calculation precision.

How to maintain these details

Label reporting coverage and upload time separately. An editor can maintain an upload note manually. An automatic timestamp needs the data-loading process to record successful uploads.

Set percentage display formats on each chart and table while retaining calculation precision. Neither task needs a custom chart renderer.

A short dashboard review

Use the official dashboard and keep the same hospital, location and explicit dates while comparing results. Use the matching known-results dashboard for the numerical examples.

  1. Read Month, Quarter and Year.Change Time Unit. Check wording, chronological order, both edges and missing labels on all eleven date charts.
  2. Try February–March, grouped as Quarter.January must stay excluded. In the known-results example, hospital 91 has ten submissions for this window.
  3. Clear, reselect and use the contents links.Choose the same hospital again. Its results should return without reloading; section links should preserve selections.
  4. Check empty, missing and zero separately.A hospital not selected, a month without observations and a measured zero should be distinguishable.
  5. Repeat after an edit or import.Check the latest-data card, comparison selectors and chart relationships as well as the main trends.

For feedback, include the dashboard version, hospital, location, dates, grouping and a screenshot of what was unexpected.
