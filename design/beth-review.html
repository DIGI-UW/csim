Review the CSiM dashboard with Beth

Start with the full September dashboard on official Superset 6.1.0. This page separates what is ready to review, what Superset still does poorly, and the source-data decisions that the dashboard cannot make for the team.

What to review

Date rangeTime Period opens in Custom. Enter a start date and an exclusive end date in the left sidebar.
Month, quarter or yearTime Unit changes how the selected observations are grouped. It does not change the date range.
Latest reporting monthThe card shows the last observation month inside the chosen Time Period. It is labelled as an observation month, not an upload date.
Comparison contextThe lower comparison charts carry the selected hospital or comparison group in their legend so a screenshot remains understandable.
Section linksTable of Contents links point back to this dashboard and keep the active filter state.
Dashboard contentThe September explanations, latest-month card and all 21 reporting charts are retained. Dataset names remain familiar to editors.

Five-minute review

  1. Choose a hospital and a date range in the left sidebar.
  2. Switch Time Unit from Month to Quarter to Year. Confirm that the values, order and labels remain understandable.
  3. Check the latest-reporting-month card and one main trend.
  4. Choose Your hospital and Cohort/State, then inspect the lower comparison legends.
  5. Use one Table of Contents link and confirm the same choices remain selected.

Known official 6.1.0 limitation

Clear all, then reselect in the left sidebar can leave a stale result. Moving filters to the left does not repair that Superset behavior. For this review, change individual selections or reload the dashboard after Clear all.

Reproduction: choose a hospital, use Clear all, then choose the same hospital again without reloading. The browser check below reselected hospital 31, but Superset combined it with the stale Cohort value and left the date range empty, exposing February 2030. The custom Superset comparison contains a source-level repair; the recommended dashboard intentionally stays on the official build.

Two decisions needed from the team

1. Hospital 53: What source rows or calculation produce the expected all-time total of 500? The supplied demonstration database contains 980 distinct historical records for hospital 53 and no current records, so changing the dashboard to 500 without that source would invent a rule.
2. Historical-to-individual transition: For each hospital, what is the first month that should come from the individual dataset? The proposed rule is historical data before that month and individual data from that month onward. The dashboard needs the approved per-hospital schedule and the rule for hospitals with no transition date.

Roster correction: hospital 58 has demonstration records but no entry in the supplied hospital/state lookup, so the current query excludes it. Add the approved hospital name, state and cohort mapping rather than guessing those values in the dashboard.

What is part of this delivery

The recommended result is a versioned dashboard, datasets and ordinary Superset configuration that run on official Superset 6.1.0. No Superset application code change is required for the dashboard improvements above. The standalone aggregate download remains available to administrators, but it is not linked from the hospital-facing dashboard.

The separate custom and development installations remain comparisons for control and importer improvements. They are not dependencies of this dashboard.
